# 个人系统

当前版本：7.2.1。只维护浏览器扩展，Codex 个人系统插件方案已舍弃。

GitHub 仓库：[JUHUAX/personal-system](https://github.com/JUHUAX/personal-system)。
`usable-v1` 分支保留可用版 V1（7.1.1），`main` 为后续改进版；版本说明见 [VERSION.md](./VERSION.md)。

## 安装

1. 在 Chrome 或 Edge 的扩展管理页面打开开发者模式。
2. 选择“加载已解压的扩展程序”，选择本目录（包含 `manifest.json`）。
3. 点击扩展图标打开“今日”工作台。
4. 更新代码后先结束当前计时，再重新加载扩展、刷新工作台。

运行扩展不需要安装 Node.js、Python 或开发依赖。未连接 Notion/LLM 时，番茄钟、时间记录和灵感仍可在本机使用。

## 配置

在“配置”页填写 Notion Token 和已授权给该连接的父页面，点击“检查并初始化工作区”，然后测试连接。初始化会复用、升级或创建六个数据源，详见 [NOTION_INTEGRATION.md](./NOTION_INTEGRATION.md)。

在“模型与外观”中填写 LLM 接口地址、模型 ID 和 API Key。扩展直接调用兼容 Chat Completions 的 HTTPS 接口，不依赖 Codex 插件或额外服务。接口、模型和密钥以用户保存的设置为准。

设置个人节奏：时区、每周工作窗口、固定安排、指定日期例外，以及用于排程估算的工作/休息时长。计时器自身的时长设置与排程估算分开。

定时双向同步默认间隔为 10 分钟；每日总结和日内自动调整分别启用。关闭定时同步时，待同步队列仍保留，可点击顶部“待同步”立即写入。

## 使用

- **今日**：优先展示待办、生活记录与灵感；完成情况、时间流、当天总结和阶段计划默认折叠。当天时间块可切换实际记录与计划。待办用复选框完成或撤销，开始、编辑、删除收进右键菜单。
- **时间记录**：时间块支持按周/按日查看、实际/计划切换，窄屏默认按日；时间流按日期切换，另有灵感草稿本和每日生活记录。真实时间块可编辑、复制、删除；自然语言“补充记录”先保存本机，再尝试同步 Notion，不据此自动创建或完成待办。
- **阶段计划**：输入日期范围与目标，拆分每日里程碑；支持编辑、调整、延长、提前结束及阶段总结。已结束计划保留历史。
- **完成情况**：番茄钟结束后只填写实际完成内容，不再填写轮次或评分。评价按时间标记追加到当天完成情况末尾，不重排手写内容；历史结构字段保留。
- **每日复盘**：保存当天完成情况，再生成总结和次日待办。次日没有有效阶段计划或工作窗口时，只保存总结与归档。
- **灵感草稿本**：连续文本框显示全部已有灵感，当天内容在末尾，可切换书写/阅读模式；日期结束后自动在该日内容后插入日期分界线，没有内容的日期跳过。输入自动保存本机，与每日时间流中的灵感输入共用存储。阅读切换不改动原文。
- **生活记录**：今日待办下方填写睡眠、三餐、心情、甜水等自然语言记录，自动保存。“时间记录 → 生活记录”按周展示每日卡片，默认阅读，点击编辑修改；只显示已有内容和今天，选择日期可补记空白历史日。单日最多 18000 字。不调用模型、不推断未写的信息，也不把生活记录用于工作自动排程。
- **Notion 页面**：在相关阶段计划、待办、总结、归档或个人节奏内容上右键查看，不再显示独立查看按钮。待办卡片也支持键盘菜单键或 Shift+F10。
- **统计**：优先展示工作时长、完整番茄、记录天数、工作比例与四个主要图表；全年记录、历史比较、文字总结默认收起。只统计已保存的真实记录，虚拟“未记录时间”不写入存储、不参与 Notion 同步。
- **界面与主题**：左侧导航切换主要页面；阶段计划按网格排列，详情在右侧抽屉打开，编辑/删除收进更多菜单。左下角切换明暗主题，选择保存在当前浏览器，也会同步到番茄钟小窗和网站拦截页。配置分为 Notion、模型与外观、自动化、个人节奏；时间安排逐行编辑，星期用按钮选择，兼容既有格式。时间选择器提供完整时分网格；番茄钟主要显示开始/暂停、休息和评价，其余操作在更多菜单，设置按计时、声音与检测、网站限制分类。

灵感输入与记录修改无需模型。规划、自然语言补录、待办调整及总结会调用模型；当前提示词见 [LLM_PROMPTS_V2.md](./LLM_PROMPTS_V2.md)，V1 仅保留历史快照。

LLM 请求显式发送 `thinking: { type: "enabled" }` 和 `reasoning_effort: "medium"`，开启思考并请求中等强度；正常调用、长度重试和排程修复均使用该设置。DeepSeek 官方将 `medium` 映射为实际的 `high`，没有独立的中等档位（见[官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)）。保留当前完整 V2 提示词及 few-shot，不改变模型 ID。

阶段规划中，每个任务独立给累计预期进度，计划完成为100%；明确日期任务也有比例，预期值不等于实际完成率。每日里程碑用任务进度列表保存多个任务，不把它们平均成阶段整体比例。旧计划不自动改写，新生成或调整时采用2.1契约；日常待办保存“阶段任务 ID”以沿用对应任务目标。

## 规则与边界

- 模型不得自行将待办标记为完成。程序自动完成要求标题模糊匹配、记录具备自动完成资格且真实投入达到时长阈值；手工补录不参与自动完成。
- 手动调整优先用户明确指定的内容和时间，指定时间可超出常规工作窗口；固定安排、日期、重叠和最早开始边界仍校验。自动排程不扩展工作窗口。
- 阶段/每日计划及总结有内容、字数和条数限制，结果超长会请求精简，最多重试一次，不直接截断后保存。
- 本地修改先进入待同步队列，完成同步后才可被其他设备读到。尚未同步的数据、授权、番茄钟偏好和灵感不自动共享到其他设备。
- Notion Token 和 LLM API Key 保存在当前浏览器的 `chrome.storage.local`，不写源码，不发送给另一个服务。该存储不等于加密保险箱，请保护浏览器用户配置及备份。
- 生活记录复用 Daily Review 中的独立“生活记录”Rich text 字段，首次同步自动补充字段；不新增数据库，不覆盖完成情况或总结。原文与同步状态按日期保存在 `minimalPomodoroLifeRecords:YYYY-MM-DD`，未同步的本地改动优先。每日归档及 Markdown 导出包含生活记录。
- 生活目标、结构化习惯指标及统计报告暂未实现；当前保留原文，供后续分析。未来想法仍保留在本地 `TODO.md`。

## 目录

| 文件 | 用途 |
| --- | --- |
| `manifest.json`、`background.js` | 扩展入口、后台计时协作、自动化与同步 |
| `timeline.html/js/css` | 工作台、时间记录、阶段计划与统计 |
| `design-tokens.css`、`appearance.js` | 统一视觉变量、主题持久化与 Lucide 图标 |
| `workspace.js/css` | 侧栏、页面布局、配置分类、阶段抽屉与时间安排编辑 |
| `controller.html/js/css`、`controller-bootstrap.js` | 番茄钟与置顶小窗 |
| `timer.css`、`blocked.html/js/css` | 计时器样式与番茄期间的网站访问申请 |
| `notion-client.js`、`notion-integration.js` | Notion/LLM 请求、校验、队列与界面 |
| `notion-context-menu.js` | Notion 右键菜单 |
| `inspiration-notebook.js` | 灵感日期分界线与文本解析 |
| `life-records.js` | 每日生活记录输入、自动保存、历史卡片与同步保护 |
| `llm-prompt-registry.js` | V2 公共片段、功能族模块和任务定义 |
| `llm-prompt-examples.js` | 可复用虚构数据及 few-shot 配方 |
| `llm-prompt-contracts.js` | 输入规范化、字段白名单、输出与长度校验 |
| `llm-prompts.js` | 按固定顺序组装 System，真实数据独立置于 User |
| `icons/`、`tests/` | 扩展图标、自动化测试 |
| `vendor/`、`scripts/build-icons.cjs` | 本地 Lucide 图标库、许可与扩展图标生成 |
| `local-backups/` | 本机历史设置导出，仅备份，不加载、不上传 |

## 开发验证

需要 Node.js 和 Python。扩展运行时不依赖这些开发工具。

```sh
npm ci
npm test
npm run test:browser
npm run test:design
```

浏览器测试优先使用本机 Edge/Chrome；也可通过 `BROWSER_EXECUTABLE` 指定浏览器或安装 Playwright Chromium。全部使用隔离的虚构记录和模拟扩展接口，不访问真实 Notion/LLM 或浏览器个人数据。

测试截图位于忽略的 `test-results/`；缓存、个人设置导出、密钥和本地备份不进入仓库。旧版说明与实现可从 Git 历史和 V1 分支查阅。
